### a) 回撤中断缠斗 + 动量清理语义与边界 —— ✅ 正确
- `js/game.js:901-903`：冲锋窗口早退之后、敌情检查之前优先判 `retreat` 返回 `homeRally`，回撤在 6 格敌情圈内仍接管（修复基线"回撤被贴脸敌情压住"）。测试 `tests/cavalry-auto-charge.test.js:80-114`：home 令后 3s 脱战 >6 格、`chargeDistance===0 && chargeMomentum===0`。

## 四、combat-balance 判据独立判断（审查点 f）

**结论：不构成"降断言换通过"；判据变化是对平衡意图变化的忠实适配，剩余断言仍有强判别力。**

1. 变化：`tests/combat-balance.test.js:81-88` 将"弓前排（裸露）"判据从 `notEqual(exposed.winner, team)`（裸布必败）改为 `exposed.alive <= floor(protected.alive/2)`（裸布存活≤受保护一半），同时保留三条硬断言：`protected.winner===team`、`protected.firstHit >= exposed.firstHit + 2000`、`protected.archerDamage > exposed.archerDamage`。
2. 与任务书一致：§三.4 只要求"受保护和裸露明显差别"，未要求"裸露必败"。"必败"是 def=15 时代的经验判据；def 15→10 的直接后果就是骑兵对枪基军队磨不动（QA：受保护 46 存活胜、裸露 10 存活惨胜 42.6s，4.6 倍存活差），裸布"必败→惨胜"正是本轮平衡意图，不是放水。
3. 判别力：新判据以"存活差 ≥2 倍 + 首击差 ≥2s + 弓输出差"三维共同约束，且 `protected` 必须胜（排除"双方全灭、2≤4 就过"的退化解）；实测 10≤⌊46/2⌋=23，余量充足非贴线。
4. 单条断言自身的局限（独立观察，补充而非否定）：`alive ≤ floor(protected/2)` 对"防御回退到 15"不敏感（回退下裸布 0 存活、受保护 42，`0≤21` 仍过）。但该回退由新增 `cavalry tuning` 测试（`combat-balance.test.js:20-32`，`calculateAttackDamage(sword,cavalry)===6` + `deepEqual` 钉死 def=10 及 hp/atk/speed/atkSpeed/cost/chargeSpeed）与未动的同军费克制测试（`8-14`，pikeman/cavalry/archer 双座硬胜负）**双重兜底**，整体判别力未降。
5. 其余数值断言（`battle-engine.test.js`、`morale-movement.test.js`）均为 `18*2.5-15=30→18*2.5-10=35` 一类机械换算，结构未动；`battalion.test.js` 6→8 营+骑队纯度断言、`site-traits-determinism.test.js` 历史版本 notEqual 均属增强。
